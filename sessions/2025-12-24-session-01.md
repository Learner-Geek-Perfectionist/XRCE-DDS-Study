## 🔍 调试过程

### 问题描述

ShapeDemoClient 通过 Agent 发布数据，但 ShapesDemo GUI 无法收到。

### 排查步骤

#### 1. 验证 Agent 基本功能

- ✅ ShapeDemoClient 自己发布的数据自己可以收到（loopback）

#### 2. 检查 Shared Memory 配置
- 根据 [ShapesDemo Troubleshooting](https://eprosima-shapes-demo.readthedocs.io/en/latest/troubleshooting/troubleshooting.html)
- 禁用了 ShapesDemo GUI 的 Shared Memory 和 Intraprocess
- ❌ 仍然不工作

#### 3. 修复 Domain ID
- agent.refs 中添加 `<domainId>0</domainId>`
- ✅ 解决了 `create_participant` 返回 `ERR_DDS_ERROR` 的问题

#### 4. Wireshark 抓包分析

```bash
sudo tshark -i lo -f "udp" -Y "rtps"
```

**发现**：
- ✅ Participant Discovery 正常 (`DATA(p)`)
- ✅ Endpoint Discovery 正常 (`DATA(w) -> Square`, `DATA(r) -> Square`)
- ✅ HEARTBEAT / ACKNACK 交互正常
- ✅ XTypes 类型交换正常 (`DATA(trq)`, `DATA(trp)`)
- ❌ 没有看到实际的用户数据包

#### 5. 定位根本原因

**XTypes 类型不兼容**

ShapesDemo GUI 的 IDL：
```idl
@appendable
struct ShapeType {
    @Key string color;
    long x;
    long y;
    long shapesize;
};
```

ShapeDemoClient/Agent 创建的类型可能没有 `@appendable` 注解，导致 XTypes 严格类型检查失败。

## 📚 学到的知识

### 1. RTPS 包类型

| 包类型 | 含义 |
|--------|------|
| `DATA(p)` | Participant Discovery |
| `DATA(w)` | DataWriter Endpoint Discovery |
| `DATA(r)` | DataReader Endpoint Discovery |
| `DATA` | 用户数据 |
| `HEARTBEAT` | 可靠传输心跳 |
| `ACKNACK` | 确认/否定确认 |
| `DATA(trq)` | Type Request (XTypes) |
| `DATA(trp)` | Type Response (XTypes) |

### 2. DDS 发现流程

```
1. Participant Discovery (DATA(p))
   ↓
2. Endpoint Discovery (DATA(w), DATA(r))
   ↓
3. Type Exchange (DATA(trq), DATA(trp))
   ↓
4. QoS 匹配检查
   ↓
5. 数据传输 (DATA)
```

### 3. XTypes 类型系统

- `@appendable` - 类型可扩展，可以添加新字段
- `@final` - 类型不可扩展
- `@mutable` - 类型字段可以任意顺序

当启用 `Propagation of type info` 时，DDS 会进行严格的类型兼容性检查。

## 🛠️ 使用的工具

### Wireshark/tshark 抓 RTPS 包

```bash
# 实时显示
sudo tshark -i lo -f "udp" -Y "rtps"

# 保存到文件
sudo tcpdump -i lo udp -w rtps.pcap

# Wireshark 打开分析
wireshark rtps.pcap
```

### 关键过滤器

- `rtps` - 只显示 RTPS 协议
- `rtps.sm.wrEntityId contains "Square"` - 过滤 Square Topic
