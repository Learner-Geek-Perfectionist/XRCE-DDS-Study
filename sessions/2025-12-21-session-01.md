## 📖 学习内容

### 文档: getting_started.rst (Deployment 部分)

**核心概念**:
1. **实体与操作分离**: 可以将「创建 DDS 实体」和「发布/订阅数据」分成两个独立的 Client
2. **Configurator Client**: 负责预先创建实体，运行一次后退出
3. **Data Client**: 使用相同的 client key 登录，复用已创建的实体，只负责收发数据
4. **Session 共享**: 多个 Client 可以通过相同的 client key 共享 Session 和实体

**关键代码**:
```c
// Configurator Client - 创建实体
uxr_init_session(&session, &comm, 0xAABBCCDD);  // 使用特定 key
uxr_create_session(&session);
// 创建 Participant, Topic, DataWriter 等
// 注意：不要调用 uxr_delete_session()！

// Data Client - 复用实体
uxr_init_session(&session, &comm, 0xAABBCCDD);  // 使用相同的 key
uxr_create_session(&session);
// 直接使用已有的 DataWriter 发布数据
```

**我的理解**:
> 这种设计适合资源极度受限的嵌入式设备。Configurator Client 可以是"胖"客户端（PC），
> 而 Data Client 可以是极简客户端（MCU），只需要发布数据的代码，不需要实体创建逻辑。
> 两个 Client 不能同时连接，必须顺序执行：Configurator 先退出，Data Client 再登录。

### 文档: agent.rst (配置部分)

**核心概念**:
1. **By XML vs By Reference**: 两种创建实体的方式
   - By XML: Client 发送完整 XML 配置，Agent 不需要配置文件
   - By Reference: Client 只发送名字，Agent 需要加载 agent.refs 配置文件
2. **agent.refs 文件**: XML 格式的配置文件，定义实体的 profile
3. **-r 参数**: Agent 启动时用 `-r agent.refs` 加载配置文件

**配置文件示例**:
```xml
<profiles>
    <participant profile_name="default_xrce_participant">
        <rtps><name>default_xrce_participant</name></rtps>
    </participant>
    <topic profile_name="shapetype_topic">
        <kind>WITH_KEY</kind>
        <name>Square</name>
        <dataType>ShapeType</dataType>
    </topic>
    <data_writer profile_name="shapetype_data_writer">
        <topic>
            <kind>WITH_KEY</kind>
            <name>Square</name>
            <dataType>ShapeType</dataType>
        </topic>
    </data_writer>
</profiles>
```

**我的理解**:
> By Reference 方式把配置的复杂性从 Client（MCU）转移到 Agent（PC），
> 让 Client 保持轻量。配置文件不需要"发送"给 Agent，Agent 启动时从本地读取。

### 文档: shapes_demo.rst

**核心概念**:
1. **ShapesDemo GUI**: eProsima 提供的可视化 DDS 测试工具
2. **ShapeDemoClient**: XRCE Client 命令行工具，与 ShapesDemo GUI 交互
3. **write_data 命令**: `write_data <datawriter_id> <stream_id> <x> <y> <size> <color>`
   - stream_id 1-127: Best Effort
   - stream_id 128-255: Reliable

**命令示例**:
```bash
# 创建会话和实体
create_session
entity_tree 1

# 发送红色方块到坐标 (100, 100)
write_data 1 128 100 100 50 RED
```

### 架构理解

**DDS Global Data Space 的本质**:
- 不是一个具体的服务器，而是一个**逻辑抽象**
- 由各个 DDS 实现（如 Fast DDS）通过 RTPS 协议互联形成
- Agent 内部运行 Fast DDS，创建的实体自动加入这个逻辑空间

**通信架构**:
```
ShapeDemoClient ──XRCE──▶ Agent ──DDS/RTPS──▶ ShapesDemo GUI
     (MCU)              (Fast DDS)           (Fast DDS)
```

## 🛠️ 实践操作

### 编译项目
```bash
./build.sh install
```

### 运行 Agent
```bash
cd ~/XRCE-DDS-Study/install/bin
export LD_LIBRARY_PATH=~/XRCE-DDS-Study/install/lib:$LD_LIBRARY_PATH
./MicroXRCEAgent udp4 -p 2018 -r agent.refs
```

### 运行 ShapeDemoClient
```bash
./ShapeDemoClient --udp4 127.0.0.1 2018
```

### 安装 ShapesDemo GUI
```bash
# 从源码编译
git clone --recursive https://github.com/eProsima/ShapesDemo.git
cd ShapesDemo && mkdir build && cd build
cmake .. && make -j$(nproc)

# 运行（解决 Wayland 兼容性问题）
QT_QPA_PLATFORM=xcb ./ShapesDemo
```
